# Proxy integration

`SessionDecoder::feed(direction, bytes)` returns typed parsed messages; Raw returns none, leaving transport metadata as the only observation. Bytes always remain owned by transport. On decoder error emit a decoder-failure event and permanently degrade that session to raw or close according to explicitly configured policy. gRPC is decoded over HTTP/2 framing: frames are reassembled per direction, DATA frames are split into length-prefixed gRPC messages (`grpc.message_text`, `grpc.message`, `grpc.message_length`, `grpc.compressed`), and other frame types are reported as `grpc.frame` with their type, length, stream and end-stream flag. HPACK is not decoded, so headers are counted but not interpreted. Frames larger than 32 KiB are skipped without buffering and marked `grpc.truncated`. TLS and WebSocket are not decoded.

For request blocking use `HttpDecoder::feed_available`, retaining all unforwarded bytes. Evaluate every returned complete `HttpRequest {bytes,message}` before forwarding its exact bytes, including valid prefixes when a later suffix fails. On parser failure, `take_pending()` recovers the unsupported remainder for transparent fallback. Transport reads16KiB and enforces a5-second absolute deadline for a pending request. EOF flushes an incomplete request unchanged. Parser fallback emits a diagnostic loss event; no enforcement is claimed for unsupported messages. After earlier pipelined request bytes have been forwarded, a blocked subsequent request closes the connection instead of injecting an out-of-order response. Server-to-client HTTP parsing and response blocking are not implemented.

The native parser supports strict HTTP/1.1 requests and content-length bodies: 16 KiB headers, 49,152-byte bodies, 64 KiB total buffered data. Duplicate content-length, transfer-encoding (including chunked), upgrade, Expect, malformed headers and oversized requests fail. Transport must bound read batches and total connection count. HTTP request buffering needs a deadline in transport. No raw TCP message dropping is provided.

`PluginVersion::load(module, sha256)` validates checksum, import freedom and required export types. `PluginRegistry::activate(profile, version)` atomically replaces the caller-owned registry entry; synchronize registry updates outside the data path and clone an Arc only at session creation. `WasmSession::new(version)` owns a bounded guest instance. Failed sessions cannot resume. The runtime does not own files, networking, audit, upload storage or control-plane APIs.

`TestProtocol` evaluates an installed immutable WASM version against an explicitly captured, unexpired sample without activation. It shares bounded diagnostics admission and guest limits, emits no live traffic, and returns typed parsed fields. Core audits sample tests and reads. The console exposes capture in Traffic and test-by-sample-ID in Protocols.

Native framing profiles use immutable versions and the same activation/manifest lifecycle: raw, delimiter (1–64 delimiter bytes), fixed-size and length-prefix (offset, 1/2/4/8-byte width, endianness and header-inclusive length). Each direction has separate bounded state, frames cap8192bytes and one feed emits at most32 messages. The typed `protocol.payload` includes framing headers/delimiters; framing never changes relayed bytes. DELETE `/api/v1/protocols/activations/{service_id}` restores the service parser for new sessions, with an idempotency key and durable removal acknowledgement. Existing sessions retain their decoder.

Native schemas and optional WASM `hydra_metadata` schemas are exposed in Protocols. Metadata JSON caps8192bytes/64fields, is validated and cached at module install rather than instantiating unbounded guests per listing. Missing metadata remains compatible with older ABI1 modules. See [PLUGIN_ABI.md](PLUGIN_ABI.md).

For the full decoder authoring, build, upload, sample-test and activation workflow, see [Creating and using capture decoders](CUSTOM_DECODERS.md).
